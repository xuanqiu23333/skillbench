# SkillBench v0.1 CLI Alpha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the first usable SkillBench CLI alpha: installable package, Skill parsing/resource inspection, `skillbench inspect`, example Skills, and automated CI verification.

**Architecture:** Keep the core independent of CLI/UI concerns. `project/` owns parsing and resource analysis, while `cli/` only formats normalized Pydantic models. Tests exercise core behavior first; CI runs ruff and pytest on Python 3.11.

**Tech Stack:** Python 3.11, Conda, Pydantic 2, Typer, PyYAML, pytest, ruff, GitHub Actions.

**Spec:** `docs/PRD.md` and `docs/architecture.md`

## Global Constraints

- Local-first; no cloud account or hosted dependency.
- Primary developer environment is Windows 11 with a dedicated Conda environment named `skillbench`.
- Local commands should be runnable as `conda run -n skillbench ...`.
- Codex runs on the Windows host rather than inside Docker.
- No `.venv`, Poetry, Redis, Kafka, PostgreSQL, vector database, Kubernetes, or distributed worker infrastructure for this slice.
- Core parsing and analysis must not depend on FastAPI or React.
- Failures must distinguish malformed/missing Skill input from normal inspection findings.
- Tests must not require a real external agent process.
- v0.1 ships only the minimum CLI-alpha slice before eval/adapter execution work.
